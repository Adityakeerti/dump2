# CitySense Mobile

React Native (Expo SDK 58 · Expo Router · MapLibre) citizen app for CitySense, built from `UI.jpeg`
and the artwork in `/assets`.

**The app talks to one backend only: CitySense core.** Map tiles, geocoding and routing come from
core's `/api/geo/*` proxy (OpenStreetMap stack by default), so no map or third-party API keys ship
in the app and nothing environment-specific is hard-coded — the only build-time setting is
`EXPO_PUBLIC_API_BASE_URL`.

## Screens

| Flow | Screens | Backend |
|---|---|---|
| Intro | 3 onboarding slides → "Lets goo" (Sign Up / Login) | — |
| Auth | Sign up, Login, Verify (4-digit email OTP, resend timer), Verified, Forgot password | `/api/auth/*` |
| Explore | OSM map, geofence circle around you, avatar pins, search (avatars + places), recentre | `/api/geo/*`, `/api/avatars` |
| Avatar | Hero, like / save / socials / share rail, rating, quick prompts, chat | `/api/avatars/{id}`, `/chat` |
| Townhall | Report an issue (GPS + reverse-geocoded address), my complaints, track by ID with escalation ladder, city events | `/api/complaints*`, `/api/city-events` |
| Saved | Bookmarked avatars | `/api/avatars/saved` |
| Updates | Active incidents + live feed over STOMP `/ws` | `/api/incidents`, `/topic/city-events` |
| Settings | Profile, chat language (en/hi), server, logout | `/api/auth/me` |

Explore requires a verified email; unverified sessions are sent back to Verify.

## Run the backend for the app

The app needs **this branch's** core (it adds the geo proxy, OTP and avatars):

```bash
docker compose up -d postgres-postgis
docker compose --profile app up -d --build core      # core on :8080
```

Without SMTP configured, OTP codes appear in the core log:
`docker logs citysense-core 2>&1 | grep "DEV .* OTP"`. Set `SPRING_MAIL_*` in `.env` to email them.
Seeded demo users (`citizen@citysense.dev` / `citysense123`) are already verified.

## Build the APK

Prerequisites: Node 20+, JDK 17+, Android SDK (`ANDROID_HOME`, or `~/Library/Android/sdk`, or
Homebrew's `android-commandlinetools`).

```bash
cd mobile
cp .env.example .env          # set EXPO_PUBLIC_API_BASE_URL
npm install
npm run build:apk             # -> mobile/dist/citysense-<version>.apk
```

`EXPO_PUBLIC_API_BASE_URL` is baked in at build time:

- Android emulator → `http://10.0.2.2:8080`
- Phone on the same Wi-Fi → `http://<your computer's LAN IP>:8080` (open the port in your firewall)
- Deployed → `https://…` (when core is behind a proxy, also set `GEO_PUBLIC_BASE_URL` on core)

Plain-HTTP traffic is allowed in the build only when that URL starts with `http://`.
`android/` is generated by `expo prebuild` and gitignored; edit `app.config.ts`, not native files.
The release APK is signed with the debug keystore — fine for sideloading, not for Play Store.

## Develop

First run after cloning (Node 20+, JDK 17+, Android SDK as above, an emulator or USB device):

```bash
git clone https://github.com/Adityakeerti/CitySense.git && cd CitySense
cd mobile
cp .env.example .env          # point EXPO_PUBLIC_API_BASE_URL at your core (see "Build the APK")
npm ci                        # exact versions from package-lock.json
npx expo run:android          # dev build on an emulator/device (MapLibre needs native code; Expo Go won't work)
```

`expo run:android` generates `android/`, builds the native app, installs it and starts the Metro dev
server; later runs reuse the native build and are much faster. Checks before pushing:

```bash
npm run typecheck             # TypeScript
npm test                      # motion token / policy tests
```

Animation follows the shared motion standard in [`docs/motion.md`](../docs/motion.md); use the tokens and
components in `src/motion/` (timings, `Tap`, `FadeIn`, reduce-motion) rather than ad-hoc durations.

## Known gaps

- The Verify screen's laptop illustration isn't in `/assets`; `VerifyArt` is a placeholder.
- Avatar hero images other than Amit and Gurpreet are the small (~100 px) map figures upscaled.
- The mockup's microphone buttons are omitted: core has no speech endpoint yet (agent_service's
  `/voice` isn't proxied by core).
- Avatar chat free text uses core's keyword responder, not the agent_service RAG pipeline.
